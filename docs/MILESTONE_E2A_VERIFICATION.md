# E2a — match-day authority and Elo storage prerequisites

18 October 2026. Part of E2; no point-entry API or live judge screen is introduced here.

Migration 022 adds physical hall tables, immutable judge-assignment revisions and validated current heads. Organizer/Main Judge may assign an active Line Judge, release duty, or explicitly take over as the acting official with a reason on the current venue date. One table/date has one owner, and a person cannot own two tables on that date across tours. Receipts and audits retain every earlier assignment; exact retries do not rewind a newer head. Current authority derives the venue date from the saved timezone and rechecks roles, active status, configured table bounds and tour dates.

Private predicates and history tables grant no direct scoring or rating writes. Former judges may read their own assignment history; current heads and unrelated assignments remain scoped. Inactive staff, removed roles, another table/date and anonymous requests have no current scoring authority. E2b must bind this authority to the actual match/table lease and hold ownership while committing a command. The shared-hall policy is delegated decision I06; full allocation/rest/manual overrides remain F.

The confirmed Elo formula now fits player/history storage above the provisional 100000 ceiling, retaining nonnegative finite whole ratings within serialization precision. A preflight found zero incompatible local current/history rows and zero oversized K settings. No stored rating/history value was changed. SQL and the existing configuration form reject unsupported K precision before match day; staff still have no direct rating mutation permission.

Verification: typecheck, zero-warning lint, 125 unit tests, production build, formatting/diff checks pass. All 514 pgTAP assertions pass on the existing database and a separate project recreated from empty volumes with all twenty-two migrations. The temporary project was stopped; original records/accounts were preserved. The new 41 assertions cover assignment/retry/conflict, once-per-date ownership, current-day takeover/release, old receipt behavior, history/head integrity, revoked-role/inactive-token denial, wrong-day denial and numeric/direct-API constraints. Synthetic tests use high table numbers, leaving ordinary twelve-table local activity untouched. Existing tournament-configuration browser scenarios pass on desktop/mobile after the K precision input change.

Assignment administration avoids holding a tour row lock while waiting for a scoring-owner head. Future result completion must acquire its tour/settings lock after scoring ownership; holding those locks in the reverse order would deadlock a takeover. `npm run test:table-owner-concurrency` proves a takeover waits 2,027 ms for an in-flight owner while the result tour lock commits without deadlock; both transactions succeed and one new head is retained. Disposable fixture records are removed afterward.
