# E3b1 — immutable correction proposal and dependency review

18 October 2026. Migration 027 adds manager-only immutable proposals against completed singles results, review state/events and a deterministic preview. I08 records this delegated workflow. No correction apply endpoint or official UI is exposed by this prerequisite batch; current official results stay in effect until E3b2 applies a reviewed amendment atomically.

Played proposals must have a valid terminal score matching their winner; recorded timeout use is retained. Automatic proposals preserve actual played history. Exact UUID/payload/actor retries return one record/event. Unchanged/invalid scores, stale base results, conflicting IDs and unauthorized/inactive callers fail. Requests/events cannot be rewritten directly; anonymous and Trainer access is denied.

Preview evaluates singles in order and stops at the corrected first third win, rather than counting later games that would no longer decide that match. It identifies later started/finished singles, pending games needed to resume, provisional/final group order and qualifier changes, both winner/loser branches and transitive dependent matches. Started affected play requires Organizer resolution. Versions and a deterministic plan digest support later apply CAS checks. Only dependency status/submission flags are included; hidden selections remain absent. Superseded/cancelled bases are marked stale.

The new SQL checks cover Main Judge review, exact retry/conflict/stale behavior, terminal score validation, same-winner totals, resumed games/group provisional status, unchanged official status/result/rating, automatic proposal history/Elo preservation, corrected first-third-win truncation, started later singles, both dependency branches plus a grandchild, direct mutation/approval forgery, deactivation and role/anonymous denials. Historical test-only graph nodes isolate preview branches; ordinary graph generation and resource checks remain covered separately.

The race script overlaps correction submissions 1,950 ms and proves a single immutable event. Finishing-point races pass (1,755/1,905 ms) with exact-once result/Elo/history/advancement, and an explicitly observed exclusive replay wait. Fixture cleanup removes correction event/state/request references before parent games/results and preserves existing league records.

Validation: all 726 pgTAP assertions pass on the existing local database. The retained isolated-install test log also records 726 passing assertions; all 27 migration files and all 18 SQL test files in that stopped project match the current workspace byte-for-byte. Typecheck, zero-warning lint, 125 unit tests, production build, formatting and diff checks pass. SQL/TypeScript parity passes for 1,743 score transitions, 508 Elo vectors and four team outcomes.

The initial browser run encountered reset connections on Docker's published local API port while the API remained healthy inside its container. Restarting only the local gateway/database and test-mailbox containers restored forwarding without resetting volumes. The complete rerun passes all 30 desktop/mobile browser scenarios, the Auth invitation/session/recovery scenario and all 726 assertions through the normal Supabase CLI. No product screen changes in this batch; existing responsive scoring/lineup flows are the regression scope.

This is review infrastructure, not completed E3: applying amendments, resetting/resolving affected attempts, continuing unfinished team matches and official controls still follow. The original requirements PDF and league records remain preserved.
