# Task B — staff foundation verification

17 October 2026. Implemented against the existing Phase 1 database with additive migrations `202610170002_league_staff.sql` and `202610170003_staff_profile.sql`.

## Delivered

- Normalized coexisting Organizer/Main Judge/Trainer/Line Judge roles, active accounts, live RLS permission checks and Organizer-only account RPCs. Legacy ownership/metadata never grants league staff authority. Trainer club assignment is intentionally implemented alongside clubs in C; no club data is exposed in B.
- Retired public signup and organization onboarding in application actions/routes and database grants. Existing organization data/audit history is retained. The historical foundation test grants the old RPC only inside its rolled-back fixture transaction; the staff suite separately asserts its actual grant is revoked.
- Organizer provisioning reserves an immutable Auth UUID in a pending/failed/complete job, creates the Auth identity through an isolated server-only admin interface and activates roles through the caller's authorized RPC. Retry/payload conflict checks prevent identity reassignment and duplicate activation. No password is stored in jobs/audits or returned in action state. Existing-email conflicts fail closed instead of linking an unrelated account. An initial password is manually shared; no invitation email is claimed.
- Organizer role/access changes preserve audit before/after state, prevent self lockout and serialize administration. Deactivation immediately removes database authority, then bans Auth; a provider failure reports the saved database state and offers a retry by saving again. Password resets have an operation receipt. Trusted bootstrap is service-only and refuses once an active Organizer exists.
- Localized RU/KK/EN staff shell, directory, account controls, login/recovery/password/profile forms and safe legacy redirects. Non-Organizer directory requests fail closed before querying the directory. Seasons/settings/teams/hall UI remains later work.
- HTTP-only staff cookies, secure in production, Lax/path=/, server refresh/proxy propagation, no-store private responses, no authenticated browser Supabase client and strict callback destinations. Recovery-only OTP confirmation; legacy signup confirmations are rejected.

## Corrections found by verification

The current CLI maps `[auth.email].enable_signup` to `GOTRUE_EXTERNAL_EMAIL_ENABLED`; disabling both flags disabled email login. Correct configuration keeps email provider enabled and `[auth].enable_signup=false`. Direct provider signup rejection and staff login are both tested. Browser tests were also corrected to await route transitions/mutation feedback and exclude Next's route-announcer alert before asserting form/callback results. The concurrency harness initially observed buffered psql output after commit; it now uses a database-observed barrier and asserts actual overlap.

## Limits

These are local integration results, not hosted deployment/readiness evidence. Hosted global-signup settings, SMTP, server secret, secure-cookie behavior on the actual HTTPS origin and bootstrap must be configured/retested at deployment. Database authority remains removed even if a subsequent Auth ban fails. Auth and SQL are separate systems; interrupted provisioning may leave an unprivileged Auth identity until an authorized retry succeeds. Recovery remains subject to provider rate limits; the UI response is enumeration-safe. Public competition pages, team scope and future operational endpoints are not implied by the staff foundation.
